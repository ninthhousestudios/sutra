## what works

- `sutra_add_root` auto-registers + async-parses any workspace
- Guard blocks Glob/Grep when index exists, redirects to sutra tools
- Guard blocks edits to load-bearing files until `sutra_impact` is called
- PageRank computed on file dependency graph, distributed to symbols
- Incremental rollup recompute (dirty set + depth-1 neighbors)
- Warm-start PageRank from existing values on reparse
- Batch SQL writes for pagerank updates

## next steps

### v0.2.0 candidates

- **Incremental parse** — Only re-parse files changed since last parse (by mtime or git diff). Currently full file walk + content-hash check every time.
- **Parallel file parsing** — `config.parse_parallelism` exists but is unused. File parsing is sequential. Use rayon or tokio::spawn.
- **sutra_refactor_plan** — Generate ordered refactor steps with safety annotations.
- **Test gap analysis** — Identify symbols with high blast radius but no test coverage.
- **Watch mode** — File watcher that triggers incremental re-parse on save.
- **Cross-workspace refs** — Resolve symbols across workspace boundaries.

### known limitations

- Workspace ID derived from directory basename only — two dirs with same name collide.
- `add_workspace` TOML write is not atomic (single-user, not a practical issue).
- Routing guard has no per-query escape hatch (only global SUTRA_GUARD_DISABLE).
- PR*1000 scaling in map importance formula is a magic number, not documented.
